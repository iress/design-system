# Token Usage Documentation Workflow

## Overview

This document explains how token usage documentation flows from Storybook to the MCP server.

## Key Principle

**Storybook is the single source of truth. The MCP server is a documentation reader, not a writer.**

The MCP server should NEVER hardcode documentation content. All documentation originates in Storybook and is consumed by the MCP server through generated markdown files.

## Workflow

```
┌─────────────────┐
│   Storybook     │  1. Create MDX files with token usage examples
│   (Source)      │     Location: packages/components/docs/StylingProps/
└────────┬────────┘
         │
         │ Doc Generation
         │ (Automatic)
         ▼
┌─────────────────┐
│  Generated      │  2. Generated markdown files
│  Docs           │     Location: packages/mcp-server/generated/docs/
└────────┬────────┘     Pattern: components_styling-props-usage-*.md
         │
         │ Read Files
         │ (Runtime)
         ▼
┌─────────────────┐
│  MCP Server     │  3. MCP tools read from generated docs
│  (Consumer)     │     Tool: get_design_tokens_usage
└─────────────────┘
```

## Documentation Structure

### Storybook Files (Source of Truth)

Located in `packages/components/docs/StylingProps/`:

**Enhanced Existing Files (not new):**

1. **010-Reference.mdx** - Enhanced with best practices and anti-patterns
   - Best Practices section: When to use styling props vs iressCss() vs CSS
   - Common Anti-Patterns section with ✅ DO / ❌ DON'T examples
   - Decision guide for choosing styling approach

2. **020-Colour.mdx** - Enhanced with usage guidelines
   - ✅ DO: Using semantic color tokens with styling props
   - ❌ DON'T: Hardcoded hex values or inline styles
   - Cross-reference to Tokens documentation for complete color reference
   - Interactive examples showing theme compatibility
   - Note: Full color token tables with WCAG ratings already exist in `packages/tokens/docs/` (autogenerated)

3. **070-Spacing.mdx** - Enhanced with usage guidelines and cross-references
   - ✅ DO: Using spacing tokens (xs, sm, md, lg, xl)
   - ❌ DON'T: Hardcoded pixel values
   - Cross-reference to Tokens documentation for complete spacing scale table
   - All spacing props documented with token examples
   - Note: Full spacing scale table already exists in `packages/tokens/docs/` (autogenerated)

4. **080-Typography.mdx** - Enhanced with usage guidelines
   - ✅ DO (PREFERRED): Using IressText component
   - ✅ ALTERNATIVE: Using textStyle prop with tokens
   - ❌ DON'T: Hardcoded font properties
   - Cross-reference to Tokens documentation for complete typography reference
   - Note: Full typography token reference already exists in `packages/tokens/docs/` (autogenerated)

Each MDX file has a corresponding `.stories.tsx` file with interactive comparison examples.

**Token Reference Documentation (Already Exists - Autogenerated):**

The complete token reference tables are already autogenerated in `packages/tokens/docs/`:

- Spacing scale table with all values (spacing.000 - spacing.1200) with visual examples
- Color tokens with WCAG contrast ratios and allowed foreground/background combinations
- Typography tokens with font families, weights, sizes, and line heights

These are generated into MCP server docs as:

- `generated/docs/tokens_spacing-docs.md`
- `generated/docs/tokens_colour-docs.md`
- `generated/docs/tokens_typography-docs.md`

**What We're Adding:** Usage guidelines, anti-patterns, and cross-references to the existing token documentation.

### Generated Files (Bridge)

Located in `packages/mcp-server/generated/docs/`:

These files are automatically regenerated from enhanced Storybook MDX files:

- `components_styling-props-reference-docs.md` (regenerated with best practices & anti-patterns)
- `components_styling-props-colour-docs.md` (regenerated with usage guidelines)
- `components_styling-props-spacing-docs.md` (regenerated with usage guidelines)
- `components_styling-props-typography-docs.md` (regenerated with usage guidelines)

**Important**: These files are regenerated whenever Storybook documentation changes.

### MCP Server Files (Consumer)

Located in `packages/mcp-server/src/`:

- **tools.ts** - Defines `get_design_tokens_usage` tool
- **handlers/tokenHandlers.ts** - Implements handler that READS from generated docs
- **toolHandler.ts** - Wires up the tool

**Critical Implementation Detail**:

```typescript
// ✅ CORRECT - Read from regenerated docs
const content = fs.readFileSync(
  path.join(
    __dirname,
    '../../generated/docs/components_styling-props-colour-docs.md',
  ),
  'utf-8',
);

// ❌ WRONG - Hardcoded documentation
const content = `
# Color Token Usage
...hardcoded examples...
`;
```

## Adding New Token Usage Documentation

### Step 1: Enhance Existing Storybook MDX File

Instead of creating new files, add sections to existing files:

```bash
# Edit existing MDX files in packages/components/docs/StylingProps/
# For example, to add color usage guidelines:
open packages/components/docs/StylingProps/020-Colour.mdx
```

Add new sections with:

- Clear subsection titles (## Usage Guidelines, ## Common Tokens, etc.)
- ✅ DO examples with correct token usage
- ❌ DON'T examples with anti-patterns
- Code examples that are copy-paste ready
- Quick reference tables where helpful

Then enhance the corresponding `.stories.tsx` file with comparison stories.

### Step 2: Run Doc Generation

```bash
# Generate documentation (exact command TBD)
yarn generate:docs
# or
yarn workspace @iress-oss/ids-storybook-config run build-docs
```

Verify generated file appears in `packages/mcp-server/generated/docs/`:

- File should have the same name as before (e.g., `components_styling-props-colour-docs.md`)
- Content should include your new sections
- Formatting should be preserved

### Step 3: Update MCP Server (if needed)

The category mapping in `tokenHandlers.ts` should already cover the main categories:

```typescript
// Existing category mapping (no changes needed for enhancements)
const categoryFileMap = {
  colors: 'components_styling-props-colour-docs.md',
  spacing: 'components_styling-props-spacing-docs.md',
  typography: 'components_styling-props-typography-docs.md',
  'best-practices': 'components_styling-props-reference-docs.md',
};
```

Only update if you're adding a completely new category (rare).

### Step 4: Test

1. **Test Storybook**: Verify documentation renders correctly
2. **Test generation**: Verify markdown file is created
3. **Test MCP server**: Verify tool returns correct content

## Benefits of This Approach

1. **Single Source of Truth**: Storybook is the authoritative source
2. **No Duplication**: Documentation doesn't exist in multiple places
3. **Consistency**: MCP server always serves latest Storybook content
4. **Maintainability**: Update Storybook once, MCP server gets updates automatically
5. **User Experience**: Developers see same docs in Storybook and via AI assistants
6. **Version Control**: Documentation changes tracked in Storybook MDX files

## Troubleshooting

### Generated files are missing

```bash
# Regenerate docs
yarn generate:docs
```

### MCP server returns empty content

Check that:

1. Generated file exists in `packages/mcp-server/generated/docs/`
2. File name matches the mapping in `tokenHandlers.ts`
3. File is not empty

### Documentation is outdated

Regenerate docs after updating Storybook:

```bash
yarn generate:docs
```
